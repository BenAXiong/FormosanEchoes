# DATA_SCHEMA.md — Field Reference

Authoritative description of every field in `data/songs.json` and `data/artists.json`.
For the *why* behind design choices, see `docs/DECISIONS.md`.

---

## Encoding

- **Format**: UTF-8 JSON, 2-space indent
- **CJK characters**: Stored as literal Unicode — `"馬蘭姑娘"` not `"馬蘭姑娘"`
- **Line endings**: LF (Unix) — do not commit CRLF
- **Any script that writes these files** must use `JSON.stringify(data, null, 2)` with no ASCII-only escaping

---

## Song fields (`data/songs.json`)

### Identity

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | `string` | Yes | Format: `sof-NNNNN`. Unique. Never reuse a deleted ID. |

### Titles

Three separate fields — not interchangeable. Priority for display: `title_original` > `title_romanized` > `title_chinese`.

| Field | Type | Notes |
|---|---|---|
| `title_original` | `string?` | Song name in the indigenous script or standard orthography of the language. Authoritative. |
| `title_romanized` | `string?` | Romanized pronunciation, e.g. CIP romanization for Amis. For learners. |
| `title_chinese` | `string?` | Chinese name as used in mainstream media / YouTube / album credits. Often differs from a translation. |

At least one title field must be present. `normalizeSong` will log a validation warning if all three are absent.

**Upcoming change (PLAN.md):** `title_original` will be split into `title_original` (indigenous script) and `title_name` (official/common name). Do not conflate these in the meantime.

### Artist

| Field | Type | Notes |
|---|---|---|
| `artist` | `string?` | Raw credit string from the source. Preserve exactly as found. Do not normalize or reformat. |
| `artist_ids` | `string[]?` | Resolved links into `data/artists.json`. Generated by `scripts/link-artists.js` at build time. Do not edit manually. |

`artist` is for display. `artist_ids` is for filtering and richer metadata. Both coexist intentionally — see `docs/DECISIONS.md`.

### Language & Ethnic Group

Each axis has a claim field and an evidence field. Always populate both.

| Field | Type | Notes |
|---|---|---|
| `language_claimed` | `string?` | Must be a value from `controlled-vocab.json → languages`. |
| `language_evidence` | `string?` | Free text: what source justifies the claim. Be specific. |
| `ethnic_group_claimed` | `string?` | Must be a value from `controlled-vocab.json → ethnic_groups`. The cultural origin of the song, not necessarily the performer's background. |
| `ethnic_group_evidence` | `string?` | Free text: justification. |

**Important:** Artist ethnic background alone is not sufficient evidence for `language_claimed`. A Paiwan artist can record a Mandarin song. The evidence must relate to the song itself.

### Source & Media

| Field | Type | Notes |
|---|---|---|
| `source_platform` | `string?` | Platform name: `"YouTube"`, `"Spotify"`, etc. |
| `url` | `string?` | Primary URL for the song (may be same as `youtube_url`). |
| `youtube_url` | `string?` | Full YouTube watch URL or short `youtu.be` URL. Parsed by `getYouTubeId` and `getYouTubeStartTime` in `lib/normalize.ts`. Supports `?t=` timestamp. |
| `lyrics_url` | `string?` | URL to a lyrics source. |
| `album_or_source` | `string?` | Album name, compilation, or collection this song appears on. |

### Metadata

| Field | Type | Notes |
|---|---|---|
| `year` | `string \| number?` | Release year. Stored as string when uncertain (e.g., `"~1980"`). |
| `location_claimed` | `string?` | Specific location associated with the song (village, region). |
| `region` | `string?` | Broader region (e.g., `"Eastern Taiwan"`). |
| `genre` | `string?` | Free text. Common values: `"Traditional"`, `"Modern Folk"`, `"Gospel"`, `"Contemporary Indigenous Folk-Pop"`. Not yet controlled vocab. |
| `tags` | `string[]` | Required (defaults to `[]`). Values must come from `controlled-vocab.json → tags`. |

### Verification

| Field | Type | Notes |
|---|---|---|
| `confidence` | `ConfidenceLevel` | Required. One of: `high \| medium \| low \| unknown`. Epistemic: how sure are we the data is correct. |
| `verification_status` | `VerificationStatus` | Required. One of: `candidate \| needs_review \| checked \| approved_public \| approved_private \| rejected \| duplicate`. Workflow: where is this song in the curation process. |
| `needs_manual_verification` | `boolean` | Default: `true`. Flag for the review queue. |
| `checked_by_me` | `boolean` | Default: `false`. Personal flag — Ben has personally verified this entry. |
| `verification_notes` | `string?` | Free text. Human notes on why this song is uncertain, what was checked, or what needs follow-up. |
| `source_snippets` | `string?` | Quoted text from sources that justifies claims. Useful when the source URL is paywalled or ephemeral. |
| `date_added` | `string?` | ISO 8601 date: `"2026-05-15"`. |

### Lyrics

The `lyrics` object is optional on a song. If present, all display is gated by `show_publicly`.

| Field | Type | Notes |
|---|---|---|
| `lyrics.song_id` | `string` | Must match the parent song's `id`. |
| `lyrics.lyrics_original` | `string?` | Text in the indigenous language/script. |
| `lyrics.lyrics_romanized` | `string?` | Romanized pronunciation of the original lyrics. |
| `lyrics.lyrics_translation_zh` | `string?` | Chinese translation. |
| `lyrics.lyrics_translation_en` | `string?` | English translation. |
| `lyrics.lyrics_source` | `string?` | Where the lyrics came from (URL or description). |
| `lyrics.lyrics_rights_status` | `string?` | Rights situation: `"public domain"`, `"permission granted"`, `"fair use research"`, `"unknown"`, etc. |
| `lyrics.lyrics_notes` | `string?` | Any notes on accuracy, source quality, or concerns. |
| `lyrics.has_permission` | `boolean` | Do we have rights to use these lyrics? |
| `lyrics.show_publicly` | `boolean` | **The render gate.** Only show lyrics content if this is `true`. |

**Rule:** Never set `show_publicly: true` without also setting `lyrics_rights_status` to something other than blank. The validator in `lib/validate.ts` will warn.

## Artist fields (`data/artists.json`)

| Field | Type | Notes |
|---|---|---|
| `id` | `string` | Format: `art-NNN`. Unique. |
| `name_display` | `string` | Primary display name. Used in UI wherever a single name is needed. |
| `names_zh` | `string[]` | All Chinese name variants (including alternate characters). Used by the linker. |
| `names_rom` | `string[]` | All romanized name variants. Used by the linker. |
| `names_indigenous` | `string[]` | Names in indigenous script or orthography. |
| `zh_surname` | `string \| null` | Chinese surname component. Useful for disambiguation. |
| `ethnic_group` | `string \| null` | The artist's ethnic background. Must match values in `controlled-vocab.json → ethnic_groups`. |
| `language` | `string \| null` | Primary language associated with this artist's work. |
| `is_group` | `boolean` | `true` for ensembles, choirs, bands. |
| `active_years` | `string \| null` | Free text: `"1990–2010"`, `"2005–present"`. |
| `bio_zh` | `string \| null` | Chinese-language biography. |
| `bio_en` | `string \| null` | English-language biography. |
| `notable_works` | `string[]` | Album or song titles this artist is known for. |
| `youtube_channel` | `string \| null` | YouTube channel URL. |
| `wikipedia_url` | `string \| null` | Wikipedia article URL. |
| `sources` | `string[]` | URLs used to compile this artist's record. |
| `notes` | `string \| null` | Internal notes on ambiguities, aliases, or pending research. |

### Name aliases and linking

The artist linker (`scripts/link-artists.js`) uses **all name variants** across `names_zh`, `names_rom`, `names_indigenous`, and `name_display` to match song `artist` strings. It uses substring matching and tokenization.

To fix a broken link:
1. Add the missing name variant to the relevant `names_*` array in `artists.json`
2. Run `npm run link`
3. Verify `songs.json` now has the correct `artist_ids`

See `notes/artist_research_coverage.md` for the current list of unlinked artist strings.

## Controlled vocabulary

Canonical values live in `data/controlled-vocab.json`. Do not invent values outside this list.

| Key | Used in |
|---|---|
| `languages` | `song.language_claimed` |
| `ethnic_groups` | `song.ethnic_group_claimed`, `artist.ethnic_group` |
| `tags` | `song.tags[]` |
| `confidence_levels` | `song.confidence` |
| `verification_statuses` | `song.verification_status` |

To add a new value to any of these lists, edit `controlled-vocab.json` and update any relevant UI components that render the options.

## Public-safe vs. internal-only fields

Fields safe to render to anonymous users:

- All title fields
- `artist` (display name, not internal IDs)
- `language_claimed`, `ethnic_group_claimed`
- `genre`, `tags`, `year`, `region`
- `lyrics.*` — **only if** `lyrics.show_publicly === true`
- `youtube_url` (public video)

Fields that are internal/admin-only:

- `language_evidence`, `ethnic_group_evidence` (can contain paywalled source quotes)
- `source_snippets`, `verification_notes` (admin curation notes)
- `confidence`, `verification_status`, `needs_manual_verification`, `checked_by_me`
- `lyrics.has_permission`, `lyrics.lyrics_rights_status`, `lyrics.lyrics_source`, `lyrics.lyrics_notes`
- `artist_ids` (internal linking, not user-facing)
- `date_added`

The public demo (`app/page.tsx`) currently shows confidence and status badges — this is intentional for transparency during the prototype phase and may change post-demo.
